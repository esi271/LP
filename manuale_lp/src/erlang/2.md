# Concetti di base: Erlang sequenziale

## Numeri
Tra i tipi e come possiamo esprimere un numero abbiamo:

| Tipo | Espressione| Esempio|
|---|---|---|
| Interi | `n` | `10.` → 10|
| Float | `i.d` | `3.14.` → 3.14
| Base `b`| `b#val` | `16#FF` → 255|
| Numero in virgola mobile| `i.deoffset` | `-12.35e-2` → -0.1235| 

Mentre per gli operatori:

| Operatori | Significato | Esempio |
|---|---|---|
| `+` `-` `*` | Somma, differenza, prodotto | `10 + 2.5 . ` → 12.5|
| `/` | Divisione, restituisce sempre un float | `8 / 4 .` → 2.0|
| `div` | Divisione intera | `7 div 2 .` →  3|
| `rem` | Resto della divisione intera | `7 rem 2 .` → 1|

### Char
In Erlang non esiste un tipo carattere: un carattere è un **intero**:  
`$char` restituisce il codice del carattere:

| Espressione | Significato | Risultato |
|---|---|---|
| `$A` | Codice di `A` | 65 |
| `$a` | Codice di `a` | 97 |
| `$0` | Codice della cifra `0` | 48 |
| `$\n` | A capo | 10 |
| `$\t` | Tabulazione | 9 |

Poiché sono interi, si può fare aritmetica:

```erl
1> $a - $A .
32

2> $A + 1 .
66

3> [$A + 1] .
"B"
```
L'ultimo esempio mostra che una lista di interi stampabili viene mostrata dalla shell come stringa.

## Stringhe
Una stringa è una **lista di char**, cioè una lista di interi.  
Non esiste un tipo stringa a parte: `"ciao"` è solo un modo comodo per scrivere `[$c,$i,$a,$o]`.

La shell stampa come stringa ogni lista di interi che corrispondono a caratteri stampabili.  
Per la stessa ragione una stringa si manipola con le operazioni sulle liste.


## Atomi
> Un atomo è una costante il cui valore è il suo nome.
- Iniziamo con la lettera minuscola
- Includendolo tra apici singoli può iniziare per lettera maiuscola e contere spazi.

```erl
1> cazzola@di.unimi.it .
'cazzola@di.unimi.it'

2> 'Walter Cazzola' .
'Walter Cazzola'
```

Posso controllare se qualcosa è un atomo dalla shel con il comando `is_atom()`.

## Booleani
`true` e `false` non sono dei tipi booleani ma sono degi **atomi**.  
Infatti:

```erl
1> is_atom(true).
true

2> is_atom(false).
true
```

Funzionano come valori booleani solo per convenzione: gli operatori booleani e le guardie si aspettano proprio questi due atomi.

### Operatori di confronto

| Operatore | Significato | Esempio |
|---|---|---|
| `==` | Uguale: confronta il valore| `1 == 1.0 .` → true|
| `/=` | Diverso | `7 /= 5 .` → true |
| `=:=` | Esattamente uguale: valore e tipo | `1 =:= 1.0 .` → false |
| `=/=` | Esattamente diverso | `1 =/= 1.0 .` → true |
| `< >` | Minore e Maggiore | `3 < 4 .` → true|
| `=<` | Minore o uguale | `3 =< 3 .` → true|
| `>=` | Maggiore o uguale | `5 >= 3 . ` → true| 

### Operatori booleani

| Operatore | Significato | Esempio |
|---|---|---|
| `not` | Negazione | `not true .` → false|
| `and` `or` `xor` | And, or e xor logico valutando sempre entrambi i lati | `true xor false . ` → true |
| `andalso` `orelse` | Il secondo lato si valuta solo se serve | `5 < 0 andalso 5 < 10 .` → false|

## Tuple
Le tuple memorizzano un **numero fisso di elementi**, di **qualsiasi tipo** e complessità.  
Per dichiararla si includono gli elementi, separati con una virgola, tra le parentesi `{}`:

```erl
1> {123, "walter", cazzola}.
{123, "walter", cazzola}

2> {}.
{}

3> {abc, {'Walter', 'Cazzola'}, 3.14}.
{abc, {'Walter', 'Cazzola'}, 3.14}
```
> La struttura conta.

Vediamo questo esempio:

```erl
4> {{1, 2}, 3} == {1, {2, 3}}.
false
```

Due tuple con gli stessi numeri annidati in modo diverso **non sono uguali**.

## Liste
Le liste memorizzano un numero variabile di elementi e hanno dimensione dinamica.  
Si costruiscono con `[Testa | Coda]` dove:
- `Testa` è un elemento.
- `Coda` è una lista.

```erl
1> [].
[]

2> [1|[]] .
[1]

3> [1|[2]] .
[1,2]
```

Posso anche costruirla con `[e1, e2, ..., en]`:

```erl
1> [{1,2}, ok, []] .
[{1,2}, ok, []]
```

### Operatori
| Operatore | Significato | Esempio |
|---|---|---|
| `length(l)`| Restituisce la dimensione di `l`| `length([1,2,3]) .` → 3|
| `l1 ++ l2 ` | Concatenazione | `> [1,2] ++ [3,4] .` → [1,2,3,4]|
| `l1 -- l2` | Differenza | ` [1,2,3,4] -- [3,4,5] .` → [1,2]|

### Modulo `lists`
- `lists:map(f, l)` :

    Applica f a ogni elemento:   
    `lists:map(fun(X) -> X*2 end, [1,2,3])` → [2,4,6]
- `lists:filter(p, l)` :

    Tiene gli elementi per cui p è `true`:  
    `lists:filter(fun(X) -> X rem 2 == 0 end, [1,2,3,4])` → [2,4]
- `lists:foldl(f, acc, l)`:

    Riduce da sinistra con accumulatore iniziale:  
    `lists:foldl(fun(X,A) -> X+A end, 0, [1,2,3])` → 6
- `lists:foldr(f, acc, l)`: 

    Come `foldl`, ma da destra:  
    `lists:foldr(fun(X,A) -> [X|A] end, [], [1,2,3])` → [1,2,3]


### List Comprehension

```erl
[ X || Qualificatore1, ..., QualificatoreN ]
```
`X` calcola ogni elemento della lista risultante; ogni qualificatore è un **generatore** oppure un **filtro**:
- Un generatore ha la forma `Pattern <- Lista` ed estrae uno alla volta gli elementi della lista.
- Un filtro è un predicato o un'espressione booleana: gli elementi per cui vale `false` vengono scartati.

```elr
1> [X*X || X <- [1,2,3,4]].
[1,4,9,16]

2> [{X,Y} || X <- [1,2], Y <- [a,b]].
[{1,a},{1,b},{2,a},{2,b}]
```

## Variabili e pattern matching

### Variabili
> Una variabile è solo un nome legato a un valore e **non può essere modificata**.
- Il nome inizia con una lettera maiuscola.
- `_` è la variabile anonima: combacia con qualsiasi valore e non lega nulla.
- Le legature si creano tramite pattern matching.

### Come funziona `=`
> Il simbolo = non è un'assegnazione ma un **confronto con legatura**.

Erlang cerca di far combaciare il pattern a sinistra con il valore a destra:
- Le variabili ancora libere vengono legate.
- Quelle già legate devono avere lo stesso valore.

Vediamo degli esempi:

```erl
1> A = 1.
1

2> A = 2.
** exception error: no match of right hand side value 2
```
In questo caso nel `1` lego `A` a `1`, poi provo a cambiare il valore e ottengo errore.  
Questo perchè non si può cambiare il valore a cui è legata.

```erl
3> [B|L] = [a,b,c].
[a,b,c]

4> {A,B,L}.
{1,a,[b,c]}
```
In questo caso nel `3` `B` viene legata ad `a` e `L` a `[b,c]`.

```elr
5> {X, X} = {B, B}.
{a,a}

6> {Y, Y} = {X, b}.
** exception error: no match of right hand side value {a,b}
```
Una variabile ripetuta nel pattern forza i due valori a essere uguali.

```erl

7> 1 = A.
1

8> 1 = Z.
* 1: variable 'Z' is unbound
```
Il lato destro non può contenere variabili non legate;

```erl
9> {A1, _, [B1|_], {B1}} = {abc, 23, [22,x], {22}}.
{abc,23,[22,x],{22}}

10> A1.
abc

11> B1.
22
```
`_` ignora un elemento e `B1` compare due volte, quindi 22 deve essere uguale nelle due posizioni.

## Funzioni e Moduli

### Funzioni
> Una funzione è un insieme di clausole separate da `;` e terminate da `.`

```erl
nome(pattern11, pattern12, ..., pattern1n) [when guardia1] -> corpo1 ;
nome(pattern21, pattern22, ..., pattern2n) [when guardia2] -> corpo2 ;
...
nome(patternk1, patternk2, ..., patternkn) [when guardiak] -> corpok .
```
- Le clausole vengono **provate in ordine** finché una combacia;
- Quando una clausola combacia, tutte le variabili della sua testa risultano legate;
- se nessuna clausola combacia si ottiene l'errore `function_clause`
- Il valore della funzione è quello dell'ultima espressione del corpo
- le espressioni nel corpo si separano con la virgola.

```erlang
fact(0) -> 1;
fact(N) -> N * fact(N-1).
```

#### Guardie
Ogni clausola nella definizione di funzione può avere una condizione in più aggiungendo una **sequenza di guardie** dopo la keyword `when`.
- Una guardia semplice è una sequenza di espressioni di guardia separate da virgole.
- **Un'espressione di guardia** è un sottoinsieme delle espressioni di Erlang prive di effetti collaterali.
- La sequenza è vera quando tutte le espressioni valgono `true`.

Quindi espressioni di guardia valide sono:
- L'atomo `true` e altre costanti
- Chiamate ad alcune funzioni predefinite (BIF).
- Espressioni aritmetiche e booleane;
- Espressioni a corto circuito (`andalso`, `orelse`).

BIF:

| | | | | |
|---|---|---|---|---|
|`is_atom`/1| `is_binary`/1| `is_bitstring`/1 | `is_float`/1 | `is_function`/2|
|`is_function`/1| `is_integer`/1| `is_list`/1 | `is_number`/1 | `is_pid`/1|
|`is_port`/1| `is_record`/2| `is_record`/3 | `is_reference`/1 | `is_tuple`/1|
|`abs`/1| `bit_size`/1| `byte_size`/1 | `element`/2 | `float`/1|
|`hd`/1| `length`/1| `node`/0 | `node`/1 | `round`/1|
|**`self`/0**| `size`/1| `tl`/1 | `trunc`/1 | `tuple_size`/1|

### Moduli
Erlang organizza i file tramite moduli: un modulo è un file `.erl`.  
I file possono contenere diverse funzioni, caratterizzate per nome e arità, che vogliamo rendere accessibili:

```erlang
-module(ex_module).
-export([double/1]).

double(X) -> double(X, 2).
double(X, N) -> X * N.
```
- `-module(nome).`: `nome` deve coincidere con il nome del file
- `-export([nome/arità, ...]).`: elenca le funzioni visibili dall'esterno. Dobbiamo specificare il loro nome i il numero di argomenti richiesti per ogni funzione che vogliamo rendere visibile.

In questo esempio `double/1` si può chiamare da fuori, mentre `double/2` è locale al modulo.  
`double/1` e `double/2` sono funzioni diverse.
