Uguaglianza strutturale vs fisica

  • Strutturale (=, <>): confronta il contenuto dei valori, scendendo ricorsivamente nella struttura.

    let s = "ciao";;
s = "ciao";;

    Restituirà true perchè il contenuto è il medesimo.

  • Fisica (==, !=): confronta l’identità, cioè se i due valori sono lo stesso oggetto in memoria (stesso indirizzo).

    let s = "ciao";;
s == "ciao";;

    Restituirà false perchè sono due indirizzi diversi.

Funzioni e costrutti

In OCaml (come nel $\lambda$-calcolo) una funzione è un valore come un altro: può essere:

  • passata come argomento
  • restituita
  • assegnata ad un nome
  • lasciata anonima

Definizione

La forma esplicita è:

let <nome> = fun <parametri> -> <corpo>

Dove:

  • fun <parametri> -> <corpo> è la funzione
  • let <nome> = ... è solo un’etichetta attaccata a quel valore.

Altrimenti abbreviando:

let <nome> <parametro> = <corpo>

Posso anche riferirmi alla stessa funzione con un’etichetta diversa:

let succ = fun x -> x + 1;;
let succ' = succ;;

succ non è altro che un’alias, stesso valore ma etichetta diversa.

Funzione anonima

Una funzione anonima è una funzione senza label ad etichettarla:

fun x -> x+1;;

Più parametri

Non esiste davvere una funzione a $n$-argomenti: è una catena di $n$ funzioni a un argomento, annidate.
Questo è proprio ciò che rende possibile l’applicazione parziale.

let f = fun x -> fun y -> fun z -> <corpo>

O più compatto:

let f x y x = <corpo>

Applicazione

Per applicare una funzione basta fare:

f x

Questo corrisponde a $f(x)$, stesso ragionamento anche per funzioni anonime:

(fun x -> x + 1) 2

Le funzioni sono associative a sinistra

f a1 a2 a3;;

corrisponde a:

(((f a1) a2) a3);;

Il corpo

Il corpo di una funzione non va visto proprio come una sequenza di comandi, ma come delle espressioni valutate e restituirà l’ultima istruzione valutata.

let <nome> <x> =
    <exp1>;
    <exp2>;
    <exp3>;;
(*Restituisce exp3*)

Corpo semplice

let succ x =
    x + 1;;

In questo caso il corpo è già un’unica espressione.

If-then-else

let fact n acc =
    if n <= 1 then acc
    else n;;

Il risultato è il valore del ramo effettivamente valutato. Entrambi i rami devono avre lo stesso tipo.
Si possono concatenare più rami:

if ... then
else if ... then
else ...;;

Nomi temporanei locali

È possibile introdurre valori intermedi o funzioni ausiliarie locali con la sintassi:

let <ausiliaria> = <espressione> in <resto_del_corpo>

Ad esempio:

let idx l x =
    let rec idx2 l x acc =
        if (List.hd l) == x then acc
        else idx2 (List.tl l) x (acc + 1)
    in idx2 l x 0;;

In questo caso idx2 fa il lavoro sporco ma resta nascosta a chi usa idx.
Catene di let...in si annidano implicitamente, uno dentro al successivo:

let calcolo x =
    let a = x + 1 in
    let b = a * 2 in
    let c = b - 3 in
    c;;

Dentro un let ... in, and può essere usato per collegare più valori definiti allo stesso livello, calcolati indipendentemente l’uno dopo l’altro:

let s = ...
and t = ...
in ...

Pattern matching

Il pattern matching serve a scomporre il valore stesso mentre decide quale ramo prendere, e dà accesso diretto ai pezzi interni:

match expression with
    | pattern1 when boolean_expression -> expression1
    | pattern2 when boolean_expression -> expression2
    | _ -> expression3;;

I rami vengono provati in ordine dall’alto verso il basso e vince il primo che corrisponde.
_ è il catch-all.

Possiamo omettere nella dichiarazione della funzione il parametro su cui andiamo a fare pattern matching usando questo zucchero sintattico:

let func = function
    | pattern1 when boolean_expression -> expression1
    | pattern2 when boolean_expression -> expression2
    | _ -> expression3;;

È possibile include nel pattern matching più espressioni e poi matchare con i vari pattern:

match expression1, espression2 with
| pattern1, pattern2 when boolean_expression -> expression3
| pattern1, pattern2 when boolean_expression -> expression4
| _ -> expression5;;

Ricorsione

Per dichiarare una funzione ricorsiva dobbiamo usare la keyword rec nella sua dichiarazione, altrimenti la funzione non sarà visibile nel suo corpo e dunque non potrà essere chiamata:

let rec f n =
    ... f...;;

A seconda di come viene fatta la chiamata ricorsiva distinguamo tra:

  • Ricorsione non in coda: rimane del lavoro da fare dopo la chiamata ricorsiva, quindi ogni chiamata resta in attesa sullo stack.

    let rec fact n =
    if n <= 1 then 1
    else n * fact (n-1);;

    Dopo la chiamata resta da moltiplicare e quindi si accumulano gli stack.

  • Ricorsione in coda: la chiamata ricorsiva è l’ultima operazione, e quindi si comporta come un ciclo senza accumulo di stack.

    let rec fact_aux n acc =
    if n <= 1 then acc
    else fact_aux (n-1) (n*acc);;

    Niente da fare dopo la chiamata.

Il trucco per trasformare una funzione ricorsiva in tail-recursive è quasi sempre lo stesso: introdurre un accumulatore che porta il risultato parziale, invece di lasciarlo sospeso nello stack.

Mutua ricorsione tra funzioni

Quando più funzioni si chiamano a vicenda (non solo sé stessa), let rec da solo non basta ma serve collegarle con and, così che tutti i nomi siano visibili contemporaneamente in tutti i corpi fin dall’inizio:

let rec is_even = function
    | 0 -> true
    | 1 -> false
    | n -> is_odd (n-1)
and is_odd = function
    | 0 -> false
    | 1 -> true
    | n -> is_even (n-1);;

Collezioni e tipi definiti dall’utente

Collezioni

Liste

let l = [e1; e2; e3; ...; en];;

Sono:

  • Omogenee.
  • immutabili: quando sembra che modifichiamo una lista, magari con l’operatore cons, in realtà ne stiamo creando una nuova.
  • Acesso sequenziale.

Operatori

Tra gli operatori di base abbiamo:

  • cons ::

    Indica la concatenazione tra un elemento e una lista: e :: l.

    e :: [e1; e2; e3];;

    Otteniamo [e; e1; e2; e3].
    Può essere usato per fare pattern matching strutturale della lista:

    match l with
    | hd :: tl ->...;
    | [] -> ...

  • concatenazione @

    Concatena due liste:

    [e1; e2] @ [e3; e4];;

    Otteniamo [e1; e2; e2; e4].
    È un operatore inefficiente, per questo motivo è preferibile usare cons.

Modulo List

Del modulo List alcuni metodi di uso frequente sono:

  • List.length l: restituisce la dimensione di l.
  • List.hd l: restituisce la testa di l.
  • List.tl l: restituisce la lista data senza il primo elemento.
  • List.nth l n: restituisce l’$n$-esimo elemento di l.
  • List.rev l: restituisce la lista inversa di l.
  • List.append l0 l1: aggiunge l1 a l0.
  • List.rev_append l1 l2: inverte l1 e lo concatena con l2.
  • List.concat ll : concatena la lista di lista ll in un’unica lista.

Tuple

Sono liste eterogenee di lunghezza fissa:

let a_tuple = (5, 'a', "a string");;

È possibile accedere agli elementi tramite pattern matching strutturale:

match a_tuple with
    | (e1, e2, e3) -> ...
    | _ -> ...

Le coppie

Quando definisco una coppia:

let a_pair = (1, "w");;

Posso usare i metodi:

  • fst a_pair: accedo al primo elemento.
  • snd a_pair: accedo al secondo elemento.

Array

Gli array sono liste ad accesso diretto tramite posizione, inoltre sono:

  • omogenee
  • mutabili
let an_array = [|1;2;3|];;

Modulo Array

  • Array.make n e: crea un array di $n$ elementi con tutti gli elementi uguali a e.
  • Array.concat [an_array_1; an_array_2]: restituisce l’array ottenunto concatenando i due array.
  • Array.make_matrix n m e: crea una matrice $n \times m$ con elementi e.

Record

I record sono:

  • accessibili per nome (tramite i nomi dei campi) con la dot-notation
  • eterogenei
  • mutabili tramite la keyword mutable : sono tuple con queste proprietà.
type person = {name: string; mutable age: int};;
let r = {name = "Walter"; age = 35};;

Tipi definiti dall’utente

Alias

È il modo più semplice per definire un nuovo tipo: consiste nel dare un nuovo nome a un tipo esistente.
Qualsiasi tipo può essere “aliasato”.

type int_pair = int*int;;
let a : int_pair = (1,3);;

Varianti

Un tipo variante elenca tutte le possibili forme dei valori di quel tipo.
Ogni caso è identificato da un nome che inizia con la maiuscola, chiamato costruttore.

type variant =
    | Nothing
    | Integer of int
    | Record of {name : string; mutable age : int};;

Questi costruttori personalizzati sono usabili nel pattern matching strutturale, eventualmente ignorando le informazioni che non mi servono:

match variant with
    | Nothing -> ...
    | Integer _ -> ... (*qua non mi serve sapere il contenuto*)
    | Record {name = n; age = a} -> ...

Tipi mutualmente ricorsivi

Un tipo mutualmente ricorsivo deve essere dichiarato tramite la keyword and, così che tutti i nomi siano visibili contemporaneamente in tutte le definizioni:

type card = Card of regular | Joker
    and regular = { suit : card_suit; name : card_name; }
    and card_suit = Heart | Club | Spade | Diamond
    and card_name = Ace | King | Queen | Jack | Simple of int;;

Sistema dei moduli

Introduzione ai moduli

I moduli sono usati per realizzare tipi di dati astratti (e relative implementazioni) e per collezionare funzioni.

Sono composti da 2 parti:

  • Pubblica interfaccia (opzionale) sig ... end
  • L’implementazione del modulo struct ... end
module A:
    sig
        ...
    end =
    struct
        ...
    end;;
  • Abstract type → sig.
  • Implementazioni →struct.

Nella maggior parte dei casi non conviene fare tutto insieme nello stesso file, anzi conviene avere un file per l’interfaccia e uno o più files le varie implementazioni che rispettano l’interfaccia.

Structure struct ... end

(*Implementazione.ml*)
module A =
    struct

        type t1 = ...
        type t2 = ...
        exception ...

        let f1 ...
        let f2 ...
        let f3 ...
    end;;

Se importiamo ed usiamo questo modulo abbiamo accesso a tutte le funzioni e al vero tipo dei tipi che abbiamo dichiarato.

Usando l’interprete per importarlo basta fare:

# #use "Implementazione.ml";;
# A.f1 ...;;

Con #use il contenuto del file viene inserito nell’interprete come se lo avessi scritto a mano: il modulo A finisce nell’ambiente globale e il nome del file non conta, quindi non serve nessun prefisso.

Signature sig ... end

Le signature sono contenute in file .mli e sono le interfacce. Al loro interno posso definire operazioni pubbliche del mio tipo di dato ed eventualmente opacizzare il tipo:

(*Interfaccia.mli*)
module type B =
    sig
        type t1

        val f1 : <tipo_input> -> <tipo_output>
    end;;

In questo caso chi utilizzerà l’interfaccia sa solo che esiste questo tipo astratto t1: ne vedrà solo il nome, non la rappresentazione concreta.

Tipi astratti e tipi concreti

Consideriamo questo esempio:

module type Ex =
    sig
        type t1                  
        type t2 = int * int      
        type t3 = A | B of int   

        val f1 : t1 -> t2
    end;;
  • type t1 è astratto: chi usa l’interfaccia vede solo il nome, non la rappresentazione.
  • type t2 = int * int è concreto: la definizione fa parte dell’interfaccia, quindi chi usa il modulo sa che t2 è int * int e può usarlo come tale. Non viene opacizzato.
  • Per varianti e record vale lo stesso: se riporto la definizione nella signature, costruttori e campi restano accessibili; se la ometto, sono nascosti.

Rispetto all’implementazione, la signature:

  • opacizza i tipi dichiarati senza definizione,
  • nasconde le operazioni non elencate,
  • lascia trasparenti i tipi dichiarati con definizione.

Quindi devono contenere:

  • dichiarazioni dei tipi (astratti e/o concreti),
  • descrizione della funzione specificando nome, tipi argomenti e del risultato.

Per caricarle nell’interprete:

# #use "Interfaccia.mli";;

Il module type B entra direttamente nell’ambiente globale, quindi lo si usa come B, senza prefisso.

Coercizione di modulo

Posso prendere una struct che implementa la struttura richiesta da un’interfaccia B (quindi tipi e funzioni), e vederla attraverso questa interfaccia.

Esempio da interprete:

# #use "Interfaccia.mli";;
# #use "Implementazione.ml";;
# module C = (A : B)

Ora usando il modulo C io vedrò solo:

  • il tipo t1 che sarà astratto <abstr>.
  • la funzione f1.

Tutto il resto, presente nella struct ma non specificato dall’interfaccia viene oscurato e non è più visibile.

# C.f2;;
Error: Unbound value C.f2
# C.f1 ...;;
- : C.t1 = <abstr>

Vincolare il modulo a un’interfaccia direttamente

Invece di definire prima A e poi fare la coercizione module C = (A : B), posso dichiarare l’interfaccia direttamente nella definizione del modulo:

module A : B =
    struct
        ...
    end;;

Il risultato è lo stesso della coercizione e se la struct non rispetta la signature il compilatore dà errore.

La differenza con la coercizione di modulo è che in questo caso non resta il modulo originale A tutto visibile come invece avremo con la coercizione.

Rendere visibile un tipo astratto: with type

with type modifica una signature rendendo noto (uguale a un tipo concreto) un tipo che altrimenti sarebbe astratto.
Il resto della signature rimane opaco.

Consideriamo questa sig:

module type Set =
    sig
        type elt
        type t
        val empty : t
        val add : elt -> t -> t
    end;;

  • Senza with type:

    module IntSet : Set =
    struct

        type elt = int
        type t = int list

        let empty = []

        let add x s =
            if List.mem x s then s else x :: s

    end;;

    # #use "SetADT.mli";;
module type Set =
sig type elt type t val empty : t val add : elt -> t -> t end

# #use "IntSet.ml";;
module IntSet : Set

# IntSet.add 1 (IntSet.empty);;
Error: This expression has type int but an expression was expected of type IntSet.elt

    In questo caso all’interno di IntSet.ml i tipi astratti dell’interfaccia sono implementati con degli alias e quindi la firma di add sarebbe:
    add : int -> int list -> int list.
    Fuori, però, il vincolo : Set nasconde questi alias e la vista esterna è:
    IntSet.add : IntSet.elt -> IntSet.t -> IntSet.t

    IntSet.elt è un tipo opaco, diverso da int, e nessuna funzione della signature restituisce un elt: non posso crearne nessun valore e il modulo è inutilizzabile.

  • Con with type:

    module IntSet : (Set with type elt = int) =
    struct

        type elt = int
        type t = int list


        let empty = []

        let add x s =
            if List.mem x s then s else x :: s

    end;;

    # #use "SetADT.mli";;
module type Set =
    sig type elt type t val empty : t val add : elt -> t -> t end

# #use "IntSet.ml";;
module IntSet :
    sig type elt = int type t val empty : t val add : elt -> t -> t end

# IntSet.add 1 (IntSet.empty);;
- : IntSet.t = <abstr>

    with type elt = int rende visibile l’uguaglianza elt = int, è ciò che permette di passare 1 ad IntSet.add.
    Senza di esso IntSet sigilla elt come un tipo nuovo e nessun valore potrà entrarci.

    Invece t resta nascosto.

Regole utili:

  • Si può usare solo su tipi dichiarati senza definizione nella signature (type t): non si può ridefinire un tipo già concreto.

  • Più vincoli si concatenano con and:

    S with type key = int and type value = string.

  • Le parentesi attorno a Set with type elt = int sono facoltative.

  • Funziona su qualsiasi signature: moduli semplici, coercizioni e funtori.

Compilazione separata

I moduli e la loro interfaccia possono essere compilati separatamente, abbiamo 2 casi:

  • Nomi dei file diversi con iniziale lettera maiuscola:

    Riutilizzando l’esempio di prima abbiamo:

    • Interfaccia.mli che contiene il modulo B
    • Implementazione.mlche contiene il modulo A

    E consideriamo questo file main.ml:

    module AbsModule = (Implementazione.A: Interfaccia.B);;
open AbsModule;;

f1;;

    Il comando open nel main.ml serve per evitare di chiamare f1 usando AbsModule.f1.

    I passi da svolgere sono:

    ocamlc -c Interfaccia.mli
ocamlc -c Implementazione.ml
ocamlc -o main Implementazione.cmo main.ml
./main

    In questo caso, siccome i nomi dei file sono diversi, bisogna scrivere esplicitamente module ... sig .. end e module ... struct ... end.

    E siccome non usiamo #use dobbiamo riferirci ai moduli usando come prefisso il nome dei file.

  • Stesso nome dei file:

    In questo caso abbiamo:

    • CharQueue.mli

      type char_queue
val empty : char_queue
...

    • CharQueue.ml

      type char_queue =
| Empty
| Node of ...

let empty = ...
...

      Quindi sono i contenuti dei file sig e struct senza essere racchiusi da module ... sig .. end e module ... struct ... end

    • main.ml

      let q = CharQueue.empty;;

    I passi da svolgere sono:

    ocamlc -c CharQueue.mli
ocamlc -c CharQueue.ml
ocamlc -o main CharQueue.cmo main.ml
./main

Interfacce e moduli compilati nell’interprete

Nell’interprete si può caricare l’implementazione con #use e usare un’interfaccia compilata. Bisogna aprire ocaml nella stessa cartella in cui c’è il .cmi.

ocamlc -c Interfaccia.mli

# #use "Implementazione.ml";;
# module C = (A : Interfaccia.B);;
# C.f1 ...;;

Qui A non ha prefisso (viene da #use, che incolla il contenuto), mentre B lo ha (viene dal .cmi).

Funtori

Introduzione

In OCaML si può avere moduli in cui si chiamano altri moduli, quindi si introduce il concetto di modulo parametrico.

I funtori sono “funzioni” da strutture a strutture.

Prendono in input un modulo, che rispetta una certa signature, e produce in output un nuovo modulo.

Concettualmente questa è la sua struttura:

module Funtore (ParametroModulo : SignatureRichiesta) =
    struct
        (* Implementazione che usa ParametroModulo*)
    end;;

Con:

  • Funtore il nome del funtore
  • ParametroModulo è l’input del mio funtore che deve rispettare la signature specificata da SignatureRichiesta.

Questo significa che una volta fissate le signature delle strutture di input, i dettagli implementativi possono cambiare senza avere effetti su nessuno dei moduli che li utilizzano.

Ci sono tre fondamenti da tenere a mente:

  • i parametri di un funtore devono essere a loro volta moduli o altri funtori, non può essere un valore concreto
  • i nomi devono avere l’iniziale maiuscola e i parametri dei funtori vanno chiamati tra parentesi.
  • i moduli e i funtori non sono di prima classe.

Un funtore da solo non è un modulo utilizzabile, ha bisogno di essere istanziato. Se da una parte il funtore rende polimorfo un certo modulo, dall’altra quando viene instanziato il modulo collassa ad essere monomorfo con l’implementazione passata al modulo.

Esempio con interprete

Consideriamo questa signature StackADT.mli:

module type StackADT =
    sig
        type char_stack
        exception EmptyStackException
        val empty : char_stack
        val push : char_stack -> char -> unit
        ...
    end;;

Questo funtore balanced.ml:

module Matcher (Stack : StackADT) =
    struct
        let is_balanced str =
            let s = Stack.empty
            ...
    end;;

Lega all’algoritmo della funzione is_balanced un tipo di dato astratto Stack, l’unica cosa che sappiamo di questo tipo astratto ci è data esclusivamente dall’interfaccia StackADT.

Matcher non è ancora un modulo utilizzabile, è una fabbrica di moduli: serve applicarlo a un modulo concreto, in questo esempio ad un vero e proprio Stack, per ottenere un modulo reale.

Quindi se consideriamo questo modulo concreto UnbStack.ml che assumiamo rispetti StackADT:

module UnboundedStack =
    struct
        type char_stack = {mutable c : char list}
        exception EmptyStackException
        let empty = {c = []}
        let push stack c = ...
    end;;

Posso passarlo a Matcher:

# #use "StackADT.mli";;
# #use "UnbStack.ml";;
# #use "balanced.ml";;
# module M0 = Matcher(UnboundedStack);;
# M0.is_balanced "(()[])";;
- : bool = true

Utilizzo

Come si potrebbe intuire dall’esempio, una motivazione per utilizzare un funtore è evitare la duplicazione: infatti nell’esempio lo scopo è evitare che is_balanced venga riscritta per ogni implementazione di stack diversa.

Considerazioni

Consideriamo questo funtore:

module Matcher (Stack : StackADT.StackADT) =
    struct
        let is_balanced str =
            let s = Stack.empty
            ...
    end;;

  • Dentro il funtore Stack è visto solo attraverso StackADT.

    Quindi i tipi dichiarati senza definizione nella signature sono astratti (Stack.t è opaco) e si possono usare solo le operazioni elencate. Il corpo del funtore non può assumere nulla sulla rappresentazione concreta.

    Quindi, in generale, il parametro è visto all’interno del funzione solo attraverso l’interfaccia specificata e quindi avremo eventualmente tipi astratti e metodi opacizzati.

# module M0 = Matcher(UnboundedStack);;
  • All’applicazione il funtore non coerce l’argomento: controlla soltanto che UnboundedStack rispetti la signature StackADT.
    Successivamente nel tipo del risultato il parametro Stack viene sostituito con il modulo concreto UnboundedStack, con la sua signature vera, quindi i tipi che l’argomento rende visibili restano visibili in M0.

Polimorfismo in ML

Introduzione

Il polimorfismo permette di gestire valore di tipi di dato diversi utilizzando un’interfaccia uniforme.

  • Una funzione che può essere valutata o applicata a valori di tipi diversi è nota come funzione polimorfica.
  • Un tipo di dato che può apparire come un tipo generalizzato è definito tipo di dato polimorfico.

Il polimorfismo non è solo un vezzo teorico: è il meccanismo che permette di scrivere codice riusabile senza sacrificare la sicurezza di tipo (type safety).
OCaml/ML supporta nativamente il polimorfismo:

let compose f g x = f (g x);;

# #use "compose.ml" ;;
val compose : ('a -> 'b) -> ('c -> 'a) -> 'c -> 'b = <fun>

Tipologie di polimorfimo

  • Polimorfismo Ad Hoc:

    la funzione/metodo denota implementazioni diverse a seconda di un insieme di tipi e delle loro combinazioni.
    È supportato in molti linguaggi tramite l’overloading (sovraccarico).

    int sum(int a, int b) { return a + b; }
double sum(double a, double b) { return a + b; }
String sum(String a, String b) { return a + b; }

  • Polimorfismo Parametrico:

    tutto il codice è scritto senza menzionare alcun tipo specifico e quindi può essere usato in modo trasparente con un numero qualsiasi di nuovi tipi; è ampiamente supportato nei linguaggi di programmazione funzionale a tipizzazione statica, oppure nell’orientamento agli oggetti tramite generics o template.

    class Box<T> {
    private T content;
    T get() { return content; }
    void set(T value) { content = value; }
}

  • Polimorfismo di Sottotipo (Subtype):

    il codice sfrutta l’idea di sottotipi per restringere l’insieme di tipi utilizzabili in un particolare caso di polimorfismo parametrico; nei linguaggi OO è realizzato tramite ereditarietà e sotto-classamento (sub-classing).

    abstract class Animal { abstract String verso(); }
class Cane extends Animal { String verso() { return "Bau"; } }
class Gatto extends Animal { String verso() { return "Miao"; } }
void faiVerso(Animal a) { System.out.println(a.verso()); }

Polimorfismo parametrico

OCaml supporta il polimorfismo parametrico.
compose implementa $f \circ g$ senza alcun legame di tipo; il suo tipo (polimorfico) è:: $$ (\alpha \to \beta) * (\gamma \to \alpha) * \gamma \to \beta$$

$\alpha$, $\beta$ e $\gamma$ sono variabili di tipo indicate rispettivamente con 'a , 'b e 'c.

Tipizzazione debole

Nulla che sia il risultato dell’applicazione di una funzione a un argomento può essere polimorfico:

se non conosciamo ancora esattamente il suo tipo, allora si tratta di un tipo debole.

Il tipo è inferito “time to time”:

  • Il tipo 'a -> 'a significa che per ogni tipo 'a , questo è il tipo 'a -> 'a.
  • Il tipo '_a -> '_a significa che esiste uno e un solo tipo '_a tale per cui questo è il tipo '_a -> '_a.
# let compose f g x = f (g x);;
val compose : ('a -> 'b) -> ('c -> 'a) -> 'c -> 'b = <fun>

# let compose' = compose (fun c -> int_of_char c) ;;
val compose' : ('_a -> char) -> '_a -> int = <fun>

Possiamo quindi dire che ciò che è potenzialmente polimorfico diventa monomorfico nella pratica, quando il compilatore si trova a gestire la sua forma polimorfica.

Esempio

# let a = ref [];;
val a : '_a list ref = {contents = []}

# let b = 1::!a ;;

val b : int list = [1]

# a;;
- : int list ref = {contents = []}

La funzione ref

ref è una funzione predefinita di OCaml che crea una cella mutabile (un riferimento):

val ref : 'a -> 'a ref = <fun>

Per accedere al contenuto puntato si usa !.

  • ref [] crea un riferimento il cui contenuto iniziale è la lista vuota [] . Poiché in fase di dichiarazione non sappiamo ancora che tipo di lista conterrà (lista di interi? di stringhe? di altro?), OCaml gli assegna il tipo 'a list ref .
  • ma essendo ref [] il risultato dell’applicazione di una funzione (ref applicata a []) viene reso debolmente polimorfico: '_a list ref.
  • Quando costruisce la nuova lista b il compilatore risolve il tipo '_a list ref $\to$ int list ref e a ora avrà tipo concreto int list ref.

L’operazione di puntare la lista la rende debole e una volta che il compilatore “indovina” il tipo, questo rimane.

Usare il polimorfismo parametrico

Dichiarazione

  • Tipo polimorfico:

    type 'a <nome> = ...

    Dove 'a è la variabile di tipo (il parametro), <nome> è il nome del tipo che si sta definendo:

    type 'a option =
    | None
    | Some of 'a;;

  • Argomenti polimorfici:

    let f (x : 'a) = ...

    Oppure come si fa quasi sempre in pratica, senza annotazione esplicita e lasciando che sia il compilatore a inferire il tipo:

    # let f x = ...
val f : 'a -> ...

Errore comune

module Stack = struct
    type 'a stack = { mutable c : 'a list }
    exception EmptyStackException

    let empty = { c = [] }
    let push s x = s.c <- x :: s.c
    let pop s =
        match s.c with
          hd::tl -> s.c <- tl
        | [] -> raise EmptyStackException
end;;

# #use "adtstack.ml";;
# let s = Stack.empty;;
val s : '_a Stack.stack = {Stack.c = []}

# Stack.push s 7;;
- : unit = ()

# Stack.push s 25;;
- : unit = ()

# s ;;
- : int Stack.stack = {Stack.c = [25; 7]}

# let s1 = Stack.empty;;

val s1 : int Stack.stack = {Stack.c = [25; 7]}

# Stack.push s1 "Hello";;

Error: This expression has type string but an expression was expected of type int

empty è un valore unico condiviso definito una sola volta nel modulo, non una funzione che ne crea uno nuovo a ogni chiamata.
Il suo tipo '_a Stack.stack resta debole, e al primo uso concreto (Stack.push s 7) si “monomorfizza” a int Stack.stack per sempre, in tutto il programma.
Ecco perché anche s1 , pur essendo una nuova variabile OCaml, condivide lo stesso tipo concreto ormai fissato: non è un bug di s1, è che Stack.empty stesso è già diventato int Stack.stack a livello di modulo.

Sistemiamo rendendo empty una funzione:

module Stack = struct
    type 'a stack = { mutable c : 'a list }
    exception EmptyStackException

    let empty () = { c = [] }
    let push s x = s.c <- x :: s.c
    let pop s =
        match s.c with
          hd::tl -> s.c <- tl
        | []-> raise EmptyStackException
end;;

Playing with Fun:

Argomenti opzionali con valore di default

In molti metodi potremmo avere la necessità di utilizzare un argomento opzionale con valore di default.

let rec count ?(tot=0) x = function
    | [] -> tot
    | h::l1 -> 
        if (h==x) then count ~tot:(tot+1) x l1 else count ~tot:tot x l1

Con questa sintassi dichiariamo la presenza di un argomento opzionale tot che di default varrà 0.
Quando bisogna aggiornare il valore di questo argomenti bisogna usare la sintassi: ~<nome>:(<new_val>) che in sostanza dice di passare <new_val> come argomento con etichetta <nome>.
La presenza di un argomento opzionale ricade anche sui tipi dedotti dal compilatore:

val count : ?tot:int -> 'a -> 'a list -> int = <fun>

In OCaml un argomento opzionale deve essere definito prima di un argomento posizionale.

Iterare e maneggiare le stringhe

Non possiamo iterare sul contenuto di una stringa usando il pattern matching strutturale, nulla ci vieta di usare un indice per la posizione e accedervi al carattere corrispondente:

let rec iter f ?(k = 0) s =
    if k < String.length s then ( f s.[k] ; iter f ~k:(k + 1) s ) ;;

Un altro approccio è quello di ottenere a partire dalla stringa una lista di caratteri.

Definire un operatore

Potremmo avere la necessità di definire un operatore infisso che verrà utilizzato all’interno della mia funzione:

let qsort (>:) l =
    let rec qsort = function
        | [] -> []
        | h::tl -> (qsort (List.filter (fun x -> (x >: h)) tl) )
                    @ [h] @
                   (qsort (List.filter (fun x -> (h >: x)) tl) )
    in qsort l

In questo caso abbiato definito l’operatore >: che verrà utilizzato come un operatore infisso all’interno della mia funzione.
Quando invoco la funziona posso passare a >:

Currying & Partial Evaluation

Currying

Il currying è una tecnica per trasformare una funzione con più argomenti in una catena di funzioni, ciascuna con un singolo argomento (applicazione parziale).
Ad es.,

$$f(x,y) = \frac{y}{x} \xrightarrow{(2)} f(2) = \frac{y}{2} \xrightarrow{(3)} f(2)(3) = \frac{3}{2}$$

Il currying è una tecnica predefinita in ML.

# let f x y z = x+.y*.z;;
val f : float -> float -> float -> float = <fun>

# f 5.;;
- : float -> float -> float = <fun>

let f x y z = ... è solo zucchero sintattico per:

let f = fun x -> fun y -> fun z -> x +. y *. z

Quindi f è una funzione che prende solo x e restituisce un’altra funzione, che prende solo y e restituisce un’altra funzione, che prende solo z.
Quindi il primo argomento passato va sempre a x, il secondo a y, il terzo a z.

Valutazione parziale

Si riferisce al processo di fissare un certo numero di argomenti di una funzione, producendo un’altra funzione di arità minore.
Ad es.

$$f(x,y) = \frac{y}{x} \xrightarrow{(x=2)} g(y) =f(2, y) = \frac{y}{2} \xrightarrow{(3)} g(3) = \frac{3}{2}$$

# let f x y = y/.x ;;
val f : float -> float -> float = <fun>

# let g = f 2. ;;
val g : float -> float = <fun>

Il vantaggio si presenta quando definisco una funzione usando dei parametri con nome, in questo caso posso specificare la posizione e controllare quale funzione otterrò:

# let compose ~f ~g x = f (g x)
val compose : f:('a -> 'b) -> g:('c -> 'a) -> 'c -> 'b = <fun>

# let compose' = compose ~g: (fun x -> x**3.)
val compose' : f:(float -> 'a) -> float -> 'a = <fun>

Map, Filter and Reduce

Panoramica

  • map = applicare una funzione a tutti gli elementi della lista;
  • filter = filtrare alcuni elementi dalla lista in base a un predicato;
  • reduce = ridurre l’intera lista a un singolo valore secondo una funzione cumulativa.

Rappresentano il pattern di programmazione più ricorrente nella programmazione funzionale.

Map

Ricordiamo una possibile implementazione di map:

let rec map f = function
    | h::l1 -> f h::map f l1
    | _ -> [];;

Il modulo List ha la sua implementazione di map:

# List.map;;
val map : ('a -> 'b) -> 'a list -> 'b list

Filter

Anche per filter non è complesso fornirne un’implementazione:

let rec filter p = function
    [] -> []
    | h::l -> if p h then h :: filter p l else filter p l;;

Ma anche in questo caso il modulo List ha la sua implementazione:

  • List.filter f l: restituisce tutti gli elementi della lista l che soddisfano il predicato f.

Reduce

Anche per reduce vediamo una possibile implementazione:

let rec reduce acc op = function
    [] -> acc
    | h::tl -> reduce (op acc h) op tl ;;

Folding

reduce è un esempio di folding (piegatura), ossia, iterare una funzione binaria arbitraria su un insieme di dati costruendo progressivamente un valore di ritorno.

Le funzioni possono essere associative in due modi (sinistro e destro), quindi il folding può essere realizzato:

  • right fold:
    combinando il primo elemento con il risultato della combinazione ricorsiva del resto, ad es.

    $$0 + (1 + (2 + (3 + (7 + (25 + 4)))))$$

  • left fold:
    combinando il risultato della combinazione ricorsiva di tutti gli elementi tranne l’ultimo, con l’ultimo

Il modulo List fornisce le funzioni:

  • List.fold_left f acc l:

    val fold_left : ('acc -> 'a -> 'acc) -> 'acc -> 'a list -> 'acc

    Consideriamo la lista $[e1, e2, e3, e4]$

  • List.fold_right f l acc:

    val fold_right : ('a -> 'acc -> 'acc) -> 'a list -> 'acc -> 'acc

    Consideriamo la lista $[e1, e2, e3, e4]$

Approfondimento sulle funzioni

Funzioni con un numero variabile di argomenti

I variadici, sono funzioni chiamabili con un numero variabile di elementi.
Possiamo costruire in OCamL una serie di funzioni per ottenere questo riusultato.

OCaml non ha funzioni variadiche native. Il trucco è far sì che ogni argomento venga consumato da una funzione che restituisce un’altra funzione, e che il risultato venga passato avanti come “accumulatore”.

let arg x = fun y rest -> rest (op x y) ;;
let stop x = x;;
let f g = g init;;
  • arg x: è una funzione parzialmente applicata.
    Aspetta ancora y (l’accumulatore corrente) e rest (il “resto della catena”).
    Quando li riceve, calcola op x y e lo passa a rest.
  • op: funzione che spiega come combinare il nuovo argomento x con l’accumulatore y.
  • init: il valore iniziale dell’accumulatore.
  • stop: l’identità. Chiude la catena e restituisce l’accumulatore finale.
  • f g = g init: avvia la catena, passando init alla prima funzione.
# let op = fun x y -> x+y;;
val op : int -> int -> int = <fun>

# let init = 0;;
val init : int = 0

varargs.ml usa op e init senza definirli: vanno quindi definiti prima di caricare il file.
Al momento del #use, arg e f si legano ai valori che op e init hanno in quell’istante. Se in seguito li ridefinisco, devo ricaricare il file.

# #use "varargs.ml";;
val arg : int -> int -> (int -> 'a) -> 'a = <fun>
val stop : 'a -> 'a = <fun>
val f : (int -> 'a) -> 'a = <fun>

f (arg 1) (arg 2) (arg 7) (arg 25) (arg (-1)) stop;;
- : int = 34

Funtore per funzioni con un numero variabile di argomenti

L’approccio precedente deve essere ricaricato ogni volta che serve un tipo diverso per f.
Questo perchè op e init sono nomi globali. Se voglio passare da somma di interi a lista di stringhe, devo ridefinire op e init e ricaricare il file.
Non si può avere le due versioni contemporaneamente.

Una soluzione è usare un funtore: prende un modulo come parametro e restituisce un modulo.
Qui serve che arg, stop e f non dipendano da un op e un init globali, ma da quelli di un modulo che viene passato.

Servono tre pezzi.

  • un tipo di dato astratto (OpVarADT):

    module type OpVarADT = sig
    type a and b and c
    val op : a -> b -> c
    val init : c
end

  • Il funtore VarArgs:

    module VarArgs (OP : OpVarADT.OpVarADT) = struct
    let arg x = fun y rest -> rest (OP.op x y)
    let stop x = x
    let f g = g OP.init
end

    Il codice è lo stesso di prima, ma op e init diventano OP.op e OP.init, cioè quelli del modulo ricevuto.

    Ci dice che per usare VarArgs, serve un modulo che rispetti la signature OpVarADT che definisce tre tipi a, b, c, un’operazione op e un valore iniziale init.

  • Le implementazioni concrete:

    module Sum = struct
    type a = int and b = int and c = int
    let op = fun x y -> x + y
    let init = 0
end

module StringConcat = struct
    type a = string and b = string list and c = string list
    let op = fun (x: string) y -> y @ [x]
    let init = []
end

Ora non ci resta che applicare il funtore:

# #use "OpVarADT.mli";;
# #use "sum.ml";;
# #use "concat.ml" ;;
# #use "varargs.ml" ;;

# module M0 = VarArgs(StringConcat) ;;
# module M1 = VarArgs(Sum) ;;

# M1.f (M1.arg 1) (M1.arg 2) (M1.arg 7) M1.stop;;
- : Sum.c = 10

# M0.f (M0.arg "Hello") (M0.arg "World") (M0.arg "!!!") M0.stop ;;
- : StringConcat.c = ["Hello"; "World"; "!!!"]

Ogni applicazione produce un modulo nuovo, già specializzato. Ora si può usare entrambi nella stessa sessione, senza ricaricare nulla.

Funtore di funtore

Consideriamo di fare la stessa cosa di prima ma con delle liste generiche.
Per StringConcat abbiamo scritto a mano il tipo string ma ora vogliamo un unico modulo ListConcat che funzioni per qualsiasi 'a list.
Ma la signature OpVarADT vuole tipi semplici (a, b, c), senza parametri come invece sarebbe 'a, quindi non puoi scrivere:

module ListConcat = struct
  type a and b = a list and c = a list
  ...
end

Qui a è un tipo astratto, cioè senza definizione: per il compilatore non è int, né string, né niente. Quando poi si prova M2.arg "Hello", il compilatore risponde che “Hello” è una string ma si aspettava un ListConcat.a, e nessun valore concreto ha quel tipo.

Funtore anche per il tipo

Se non puoi parametrizzare con 'a, parametrizzi con un modulo che contiene il tipo:

module ListConcatFunctor (T : sig type t end) = struct
  type a = T.t and b = a list and c = a list
  let op = fun (x: a) y -> y @ [x]
  let init = []
end

T : sig type t end è un modulo che contiene solo un tipo t, e a viene definito come T.t.
Ora il tipo è concreto, ma lo scegli tu al momento dell’uso:

module M3 = VarArgs(ListConcatFunctor(struct type t = int end))
module M4 = VarArgs(ListConcatFunctor(struct type t = string end))

Qui ci sono due funtori annidati:

  • prima ListConcatFunctor costruisce un modulo “concatena liste di int” (o di string),
  • poi VarArgs lo trasforma in arg/stop/f specializzati.
# M3.f (M3.arg 2) (M3.arg 3) (M3.arg 4) M3.stop;;
- : int list = [2; 3; 4]

# M4.f (M4.arg "Hello") (M4.arg "World") M4.stop;;
- : string list = ["Hello"; "World"]
